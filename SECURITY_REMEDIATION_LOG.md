## 2. Itemized Remediation Log

### Remediation Entry 1: Automated Retention & Purge Worker Engine
- **Finding ID:** SEC-FIND-01
- **Severity:** High / P1 (Operational Compliance Defect)
- **Component:** `src/lib/retentionSweep.ts`, `src/lib/recurrenceSweep.ts`, `scripts/patch-worker.mjs`
- **Issue Description:**
  `customer_deletion_requests` accepted workspace deletion requests and recorded a 30-day grace period timestamp (`scheduled_purge_at`), but no automated background job existed to execute the permanent purge once `scheduled_purge_at <= datetime('now')`. The Cloudflare scheduled cron job only evaluated recurring tasks and overdue automations.
- **Root Cause:**
  The deletion request submission route was deployed during the commercial foundation setup without completing the accompanying automated purge execution routine in the cron sweep.
- **Remediation Implemented:**
  1. Created `src/lib/retentionSweep.ts` implementing `runRetentionSweepWithDb(db)`.
  2. The sweep queries due deletion requests and executes cascading deletes across 25+ relational tables (`tasks`, `pages`, `projects`, `files`, `conversations`, `calendar_events`, `subscriptions`, etc.).
  3. Single-tenant users whose sole membership was the purged workspace are deactivated (`is_active = 0`) and their active sessions revoked.
  4. The request status is marked `completed` with audit metadata.
  5. Integrated the retention sweep into `scripts/patch-worker.mjs` (injected into `.open-next/worker.js`) and `src/lib/recurrenceSweep.ts`.
- **Verification:**
  Tested with synthetic Org 3 in `test_security_audit_isolated.mjs`. Verified that active grace period workspaces are preserved, and expired workspaces are 100% cascade-purged.

### Remediation Entry 2: Session Token Retention Window Harmonization
- **Finding ID:** SEC-FIND-02
- **Severity:** Low / Medium (Policy-to-Code Discrepancy)
- **Component:** `src/lib/legalConfig.ts`
- **Issue Description:**
  In `src/lib/legalConfig.ts`, `RETENTION_WINDOWS.SESSION_TOKEN_EXPIRY_DAYS` was set to `30`, while actual authentication tokens generated by `signToken()` in `src/lib/auth.ts` and set in `login/route.ts` used a 7-day expiration (`7d`, maxAge: `7 * 24 * 60 * 60`).
- **Root Cause:**
  Generic placeholder value in legal configuration before alignment with the strict 7-day token rotation policy.
- **Remediation Implemented:**
  Updated `SESSION_TOKEN_EXPIRY_DAYS: 7` in `src/lib/legalConfig.ts` with descriptive comment.
- **Verification:**
  Verified that `/legal/data-retention` and config export now report 7 days, matching the actual browser cookie and JWT token lifetime.

### Remediation Entry 3: Automated Stale Token & Session Purge
- **Finding ID:** SEC-FIND-03
- **Severity:** Low (Database Hygiene & Minimal Exposure)
- **Component:** `src/lib/retentionSweep.ts`, `scripts/patch-worker.mjs`
- **Issue Description:**
  Revoked sessions (`revoked_at IS NOT NULL`) and used or expired password reset tokens (`password_reset_tokens`) accumulated in the database indefinitely without an automated purge query.
- **Remediation Implemented:**
  Added automated purge queries in `runRetentionSweepWithDb`:
  - Purges sessions revoked older than 7 days or expired older than 30 days.
  - Purges password reset tokens expired or used older than 7 days.
- **Verification:**
  Verified in isolated test harness and OpenNext build bundle.

---

### Remediation Entry 4: Meeting Reminder Cron Sweep Alignment
- **Finding ID:** SEC-FIND-04
- **Severity:** Low (Cron Engine Parity)
- **Component:** `scripts/patch-worker.mjs`
- **Issue Description:**
  Calendar meeting reminder dispatch was present in `src/lib/recurrenceSweep.ts` but had not been included in the worker patch script `scripts/patch-worker.mjs`.
- **Remediation Implemented:**
  Injected the meeting reminder sweep into `scripts/patch-worker.mjs` so meetings starting in the next 20 minutes automatically trigger attendee notifications via the Cloudflare Worker cron event.
- **Verification:**
  Tested during `npm run cf:build`.

## 4. Rollback & Fail-Safe Strategy

In the unlikely event that the retention sweep worker causes issues:
1. Workspace deletion requires explicit confirmation (`DELETE {orgName}`) and can only be submitted by the Workspace Owner (`role === 'owner'`).
2. Workspaces are protected by a mandatory 30-day grace period (`scheduled_purge_at`).
3. Purges only execute when `scheduled_purge_at <= datetime('now')`.
4. Git rollback point: Commit `26ff7c1`.
